# 蓝牙翻页器助手（BluetoothRemote）

给越狱 Kindle 接蓝牙翻页器的 KUAL 插件。**不用 SSH、不用敲命令**，在 KUAL 里点几下就能把翻页器上的按键绑成「上一页 / 下一页 / 熄屏」，绑定结果直接写进 KindleBTH。

> 作者：Y1-LL ｜ 许可：[MIT](LICENSE)

---

## 它解决什么问题

Kindle 要接蓝牙翻页器，底层需要两个东西：

1. **kindle-hid-passthrough** —— 把 BLE HID 设备变成系统里的 `/dev/input/eventN`
2. **KindleBTH** —— 监听那个输入节点，按配置执行翻页/亮度/熄屏动作

装好这两个之后，真正的麻烦才刚开始：

- 每个翻页器的键码都不一样，**出厂配置基本对不上**，按了没反应
- 想自己调，得用 SSH 跑 `evtest` 一个个抓码，再手改 JSON
- 同一个码如果出现在两个动作里，会出现「翻一页又翻回来」
- 有些翻页器/手柄好几个按键发的是**同一个键码**，很容易配错

这个插件把这些变成菜单操作：**点一下 → 按几下 → 自动写进配置**。

## 前置要求

以下缺一不可，**这个 zip 不包含它们**：

- 已越狱的 Kindle + 已安装 [KUAL](https://www.mobileread.com/forums/showthread.php?t=203285)
- 已安装 [`kindle-hid-passthrough`](https://github.com/zampierilucas/kindle-hid-passthrough)（路径 `/mnt/us/kindle_hid_passthrough/`）
- 已安装 **KindleBTH**（路径 `/mnt/us/extensions/KindleBTH/`）
- 翻页器已和 Kindle 完成过**一次蓝牙配对**（用 Kindle 自带蓝牙管理器或 BTManager）

> 在 Kindle Paperwhite 6（固件 `5.18.5`）上实测通过。其他机型理论通用，未逐一验证。

## 安装

1. 解压，把 `BluetoothRemote` 整个文件夹放进 `extensions/`
   （最终路径 `/mnt/us/extensions/BluetoothRemote/`）
2. 断开 USB，打开 KUAL → **蓝牙翻页器助手**
3. 第一次只有一个选项：**`[0] 初始化 / 刷新菜单`**，点它
4. **退出 KUAL 再进**，完整菜单才会出现

---

## 第一次使用：绑按键

```
[0] 刷新状态
<当前连接的翻页器名字>
[1] 上一页  (点这里开始匹配)
[2] 下一页  (点这里开始匹配)
[3] 熄屏（再按一下亮屏）  (点这里开始匹配)
[4] 亮屏（同上）
[5] 全部完成，启动翻页服务
[6] 翻页来回跳？点这里修复
[7] 查看当前键位绑定
[8] 恢复出厂键位（重学一遍）
```

**绑定步骤（以「上一页」为例）：**

1. 点 `[1] 上一页`
2. 屏幕倒数 `3 2 1`
3. 出现 `PRESS PREV PAGE` 后，**在 12 秒内连续按 10 下**翻页器上的「上一页」键
4. 出现 `[ OK ] MAPPED / PREV PAGE = key 312` 即成功
5. 退出 KUAL 再进，`[1]` 后面会显示 `已匹配: 312`

对 `[2] 下一页` 重复同样的操作。

`[3] 熄屏` 绑定后，按一下关屏、再按一下亮屏 —— Kindle 的电源键就是这个逻辑，所以 `[4] 亮屏（同上）` 不需要单独学，点开只会告诉你当前用的是哪个码。

## 菜单逐项说明

| 菜单项 | 作用 |
|---|---|
| `[0] 刷新状态` | 重新生成菜单（KUAL 只在启动时读菜单，改完要退出重进才看得到） |
| 设备名那一行 | 当前**实际连着**的蓝牙设备，来自 hid-passthrough 的 `/status` |
| `[1]`~`[4]` | 逐个绑定按键，学完自动写入 `KindleBTH/bin/config.json` |
| `[5] 启动翻页服务` | 拉起 daemon + 连接翻页器 + 启动 KindleBTH，一次到位 |
| `[6] 修复冲突` | 出现「翻一页又翻回来」时点它，按绑定记录删掉重复码 |
| `[7] 查看当前键位绑定` | 列出四个动作各自绑了哪些码，重复的会标 `*` |
| `[8] 恢复出厂键位` | 把 `config.json` 还原成默认值（会先备份） |

## 常见问题

**按了没反应？**

1. 确认 `[0]` 下面那行显示的是你正在用的翻页器名字
2. 点 `[5] 启动翻页服务`，等屏幕提示 `READY`
3. 点 `[7] 查看当前键位绑定`，看四个动作里有没有你按的那个码

**翻一页又翻回来？**

同一个键码同时出现在 `key_prev_page` 和 `key_next_page` 里。点 `[6] 修复冲突`。

**几个按键配不上，一配就把别的弄坏？**

有些翻页器/手柄的多个按键在系统层面**发的是同一个键码**，无法区分。这种情况下一个码只能绑一个功能，请换一个发码不同的键（肩键、摇杆按下通常比较独立）。

**学完菜单没变化？**

KUAL 只在启动时读菜单文件，**必须退出 KUAL 再进**（这是 KUAL 的限制，不是插件的问题）。

**熄屏没反应？**

先确认 KindleBTH 在运行（`[5]`），并且设备的背光/前光不是处于异常值。熄屏是通过模拟电源键实现的，如果系统前光被设成 0，按了会看起来「没反应」。

## 已知限制

- 只做「按键绑定 + 服务启动」，不含驱动（`kindle-hid-passthrough`）和翻页实现（`KindleBTH`）
- 不支持热切换多套键位配置（配置档功能已下线）
- 一键「启动服务」需要 `kindle_hid_passthrough` 在 8321 端口提供 HTTP API
